# RTMN — контрольна точка Етапу 1

Єдина робоча директорія: `X:\RTMN`.

## Запуск

```powershell
Set-Location X:\RTMN
npm test
npm run build
```

`npm run test:watch` запускає повторні тести після змін.

## Що перевіряється

12 тестів охоплюють каталог і категорії, пошук та порожній результат,
сортування цін, EN/DE/UA та збереження мови, вибір розміру,
закриття модалки через Escape, кількість і підсумки кошика,
поріг безкоштовної доставки, окремі розміри товару, wishlist,
блокування неповного checkout і повернення до кошика,
ініціалізацію Telegram та haptic feedback.

Тести виконуються в ізольованому jsdom. Вони не читають справжній
BOT_TOKEN, не надсилають повідомлення та не змінюють кошик браузера.
Telegram замінений тестовим об'єктом. Це не перевірка справжнього
Telegram-клієнта, платежів або створення серверного замовлення.

Production entrypoint `src/main.jsx` не змінено. Тест перехоплює
початковий виклик `createRoot`, отримує App і монтує його через
React Testing Library. Після майбутнього виділення App в окремий
модуль цей перехоплювач можна замінити прямим імпортом компонента.

## Відомі обмеження поточної версії

- Checkout показує локальний успіх без створення реального замовлення.
- Фільтри розміру й кольору та окрема сторінка wishlist ще не реалізовані.
- Cart блокує прокрутку body; на невисокому екрані нижні елементи
  можуть бути недоступні. Це потрібно виправити окремим етапом.
- jsdom не перевіряє layout, mobile viewport або поведінку WebView.

## Межі змін і відкат

Етап додає `vitest.config.js`, `src/main.test.jsx`, `src/test/setup.js`,
цей документ, scripts `test`/`test:watch` і devDependencies у package-файли.
Функціональність storefront і `.env` не змінюються.

Для відкату потрібно вилучити лише перелічені файли тестового етапу,
прибрати його scripts і devDependencies та узгодити package-lock.json
через npm. Не відновлюйте весь репозиторій поверх пізніших змін.
Git commit автоматично не створювався.
